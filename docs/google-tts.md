# Google Cloud Text-to-Speech

## Секрет и безопасность

В GitHub Actions секрет ожидается под точным именем `SPROSI_AI_OZVUCHKA`. Скрипт читает значение из `GOOGLE_TTS_API_KEY` или `SPROSI_AI_OZVUCHKA`; переменная окружения имеет приоритет. В локальной среде скопируй `.env.example` в `.env` и экспортируй ключ. Значение нельзя коммитить, вставлять в промпты, печатать в лог или включать в сообщение об ошибке.

Секрет GitHub не сообщает, корректен ли ключ, включён ли API, настроен ли биллинг и разрешён ли Text-to-Speech. Для фактической проверки запусти ручной workflow **Google TTS smoke test** и открой MP3-артефакт. Ошибка авторизации, ограничения проекта или quota будут видны в сообщении workflow без самого ключа.

## Проверка ключа в Actions

1. Открой вкладку **Actions**.
2. Выбери **Google TTS smoke test**.
3. Нажми **Run workflow** и оставь короткую фразу на русском.
4. Успешный job и артефакт `google-tts-smoke` означают, что ключ прошёл запрос к API.
5. Если шаг упал, проверь Google Cloud project, включённый Cloud Text-to-Speech API, ограничения API key и billing. Не добавляй ключ в workflow-файл или команду.

Тест вручную запускается в GitHub; при каждом push API не вызывается. Это ограничивает случайные вызовы и расходы.

## Голоса

Шаблон использует имя `ru-RU-Standard-A` с языком `ru-RU` и умеренным темпом. Перед записью выбери голос для каждого персонажа, прослушай пробу и сохрани голос во всех репликах персонажа. Если меняется голос/семейство модели, проверь его в Google Cloud Text-to-Speech voices list.

Параметры реплики: `voiceName`, `languageCode`, `speakingRate` и `pitch`. Делай отдельный аудиофайл на каждую реплику, чтобы можно было менять монтаж без повторной генерации всего эпизода. Для протяжённых пауз и сложной интонации редактируй аудио/тайминг после синтеза; не рассчитывай, что TTS сам сыграет эмоциональный подтекст.

## Локальный вызов

```bash
cp .env.example .env
# Запиши ключ в .env локально, затем выполни:
npm run tts -- --input src/episodes/episode-001.json
```

Не сохраняй настоящий ключ в shell history. Локально безопаснее экспортировать его в текущую сессию из своего менеджера секретов. Сгенерированные MP3 сохраняются в `public/audio/<episode-id>/` и исключены из Git.
